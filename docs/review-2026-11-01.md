# 프로젝트 리뷰 — 외국인 진료소 찾기 (2026-11-01)

리뷰 대상: `origin/main` (70170ab) · 브랜치 `chore/paseo-dev-env`
런타임 확인: Paseo 프록시 dev 서버 + 실제 브라우저(마커 81개, 타일 33장, 모바일 다이얼로그 동작)

## 구조

- 정적 사이트, 빌드 없음. `index.html`(CSS 인라인) + `js/main.js` + `js/config.js`
- 데이터: Google Sheets → Apps Script `doGet` → JSON → 클라이언트 fetch
- 지도: Naver Maps JS v3 (`ncpKeyId`)
- 현재 응답: 기관 81곳 (available 27 / unavailable 7 / unknown 47), programs 3종, 총 42.7KB

## 잘 된 부분

- Apps Script가 `PUBLIC_FIELDS` 화이트리스트로 노출 열을 제한하고, 오류 시 내부 정보를 숨김
- `inferStatus`가 O/X만 단정하고 나머지는 unknown으로 보수적 처리
- 클라이언트 `escapeHtml`로 XSS 방어, `coordsFor`로 범위 밖/placeholder 좌표 필터
- 모바일에서 지도 팝업 대신 다이얼로그로 전환하는 판단, 반응형 레이아웃

## 고칠 것

### P0

1. **데이터 공백** — 81곳 중 47곳(58%)이 `확인 필요`. 전화번호·주소·최종확인일은 81곳 전부 빈값이라 방문 전 확인 수단이 없음. `notes`(기타1~3)는 62건 채워져 있는데 팝업에서 렌더링하지 않음(`hospitalDetails`).
2. **status 매핑 불일치** — Apps Script는 `available/conditional/program/unavailable/unknown` 5종을 반환하지만 `loadHospitals()`는 3종만 매핑. `conditional`/`program`은 `record.support`(undefined)로 떨어져 **"확인 필요"로 오표시**.

### P1

3. **programs 미사용** — 응답의 2.7KB(지원사업 상세 3종)가 화면에 없음.
4. **접근성** — 지도 마커는 키보드/스크린리더 접근 불가, `#results`에 `role="status"` 없음, `title="좌표 정보가…"`는 번역·낭독 안 됨.
5. **공유 대비** — OG/Twitter 카드, 파비콘, 대표 설명 없음 → 카톡·텔레그램 미리보기 빈약.
6. **신선도/고지** — `lastVerified` 전부 빈값, "방문 전 전화 확인" 안내 없음.

### P2

7. 레거시: `data/hospitals.json`(40KB, 미참조), 빈 `css/`, `COMMIT_COMMENT.txt`, 한 줄 README
8. `fetch` 타임아웃/재시도 없음 → Apps Script 콜드스타트 시 빈 화면
9. `render()`의 `state.hospitals.indexOf(h)` (O(n²), 81건이라 실해는 없음)
10. 로컬 `main`이 origin보다 1앞/5뒤로 갈라져 있음(예전 `data: 실제 병원 좌표 적용`)

## 지도 팝업 × 브라우저 자동번역

현재 페이지는 조건을 이미 충족: `<html lang="ko">`, `notranslate` 없음, 팝업도 일반 `div` 텍스트 노드(캔버스/iframe 아님). 문제는 **타이밍** — 팝업은 클릭 시 `innerHTML`로 새로 생기므로 페이지 번역 이후에 열리면 번역 대상에서 빠지거나 경합으로 옛 번역이 남는다(Chromium 이슈 393698470 유형).

### 방법 A — 미리 DOM에 두고 노드를 그대로 넘기기 (검증됨)

네이버 `InfoWindow`는 넘긴 DOM 노드를 복제하지 않고 그대로 옮겨 쓴다(스테이징이 비고, close/reopen에도 같은 노드 유지 — 실제 확인). 따라서 로드 시 팝업을 만들어 화면 밖에 두면 브라우저 번역이 그 텍스트를 번역하고, 이후 열어도 번역문이 따라온다.

```js
const stage = document.createElement('div');
stage.className = 'popup-stage';   // position:absolute; left:-9999px; top:0; width:280px;
document.body.append(stage);       // display:none 금지(렌더되는 위치여야 번역 대상)

const popupNode = new Map();
hospitals.forEach(h => {
  const node = document.createElement('div');
  node.className = 'popup';
  node.lang = 'ko';
  node.innerHTML = hospitalDetails(h);
  stage.append(node);
  popupNode.set(h, node);
});
// 클릭 시
new naver.maps.InfoWindow({ content: popupNode.get(hospital), maxWidth: 300 });
// 모바일 다이얼로그는 popupNode.get(h).cloneNode(true)
```

한계: 사용자가 번역을 누르기 전에 팝업을 열면 한국어.

### 방법 B — 자체 다국어 (확실한 답)

Apps Script `LanguageApp.translate` + 번역 캐시 시트, `?lang=vi` 파라미터. 81곳 × 언어를 미리 번역해 내려주고 `lang` 속성을 언어별로 지정. 의료 용어라 검수 필요. LanguageApp은 일일 할당량이 있어 캐시 필수.

### 방법 C — 보조

팝업에 "이 내용 번역" 버튼 → 같은 Apps Script 번역 엔드포인트 호출. 브라우저 번역이 없는 인앱 브라우저 커버.

### 인식 조건 체크리스트

- `<html lang="ko">` 유지 / `<meta name="google" content="notranslate">` 금지
- 팝업 컨테이너에 `lang="ko"` 추가
- 텍스트는 실제 텍스트 노드로 (이미지·캔버스·iframe·shadow DOM 안은 번역 안 됨)
- `title`/`aria-label`만 있는 문구는 번역 안 됨 → 화면 텍스트로
- `<strong>지역</strong> 경기 / 파주시`처럼 라벨/값 분리는 번역 품질 저하 → 문단 단위 유지

## 적용 현황 (2026-11-01)

- **방법 A 적용 완료**: 팝업을 로드 시점에 `.popup-stage`(화면 밖, `left:-10000px`)에 미리 렌더하고, 클릭하면 같은 노드를 `InfoWindow.setContent()`로 넘긴다. 닫히면 스테이징으로 되돌려 문서에 남긴다. 모바일 다이얼로그는 `cloneNode(true)`.
  - 함정: `new InfoWindow({ content: node })`로 생성하면 네이버가 그 즉시 노드를 DOM에서 떼어낸다(문서에 남지 않아 번역 대상이 안 됨). 생성 시에는 `content: ''`로 두고 **열 때** `setContent(node)`를 호출해야 한다.
- 남은 작업: `conditional`/`program` 상태 라벨, OG 태그·파비콘. 다국어(B)는 접속 국가 확인 후.
